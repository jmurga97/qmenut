# Internationalization — languages & translations 🧩

> **Stub** — Purpose + key files below; expand when needed.
> Follows the [doc template](../README.md#the-doc-template).

## Purpose & status

✅ Complete. Two coordinated sub-features: **enabling languages** for a restaurant,
and **translating menu entities** (machine translation via DeepL, plus manual edits).
The public menu serves locale-prefixed routes and hreflang alternates.

## Data model

- `restaurant_languages` + `restaurants.defaultLanguageCode`
  (`packages/db/src/schema/restaurants.ts`).
- `translations` (`packages/db/src/schema/translations.ts`): `entityType`
  (`dish | category | variant_group | variant_option | ingredient`), `field`, `value`,
  `status` (`ok | pending_update`), `source` (`machine | manual`).

## Backend

- `apps/api/src/modules/admin-translations/admin-translations.router.ts` — two
  sub-routers: **`languages`** (catalog/list/add/setActive/remove/translateAll) and
  **`translations`** (list/update). Mounted in the root router as `admin.languages` and
  `admin.translations`.
- Machine translation: `deepl.service.ts`; helpers `language-catalog.ts`,
  `translate-all.ts`, `list-translations.ts`.
- Repositories: `restaurant-languages.repository.ts`,
  `admin-translations.repository.ts`, `translations.repository.ts`; model
  `packages/db/src/models/translation.ts`.

## Frontend

- Admin: `apps/admin/src/app/routes/_auth.languages.tsx`, `_auth.languages.index.tsx`,
  `_auth.languages.$languageCode.tsx`; feature `apps/admin/src/features/languages/`.
- Public i18n: `apps/web/src/lib/i18n/`; locale-prefixed routes `{-$locale}.*`;
  hreflang via `apps/web/src/features/menu/seo/build-hreflang-alternates`.

## Notes & gotchas

- `translations.status = pending_update` marks a machine/source string that changed
  and may need re-translation — surface it in the admin UI.
- DeepL is configured via env (`DEEPL_API_URL` and key); keep the key server-side.
